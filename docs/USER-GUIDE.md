# SWS Vault 使用手册

> 适用版本：dfb77598b566（2026-10-16 部署）。面板地址：`http://192.168.20.132:9531/admin`（仅内网）。
> 当前是**测试部署，走明文 HTTP**：只放测试密钥，正式密钥等 HTTPS 就绪后再录。

## 1. 它是做什么的

SWS Vault 是一个只写不读的密钥保险库。用法分两步：

1. **你**在面板里把密钥（API token 等）存进去，存进去后面板上再也看不到原值；
2. **项目**（服务器上的脚本、Hub、git 等）拿着自己的「客户端令牌」来调用，保险库只把密钥注入到它被允许发往的地址，项目本身通常拿不到明文。

记住三个词：

| 词 | 意思 |
|---|---|
| 密钥 | 你存进去的一个值，比如一个 Cloudflare API Token |
| 项目 | 一组密钥的归属，比如 `blog-deploy`。密钥只有关联到某个项目后才能被调用 |
| 客户端令牌 | 发给项目用的通行证（`swsv_` 开头），只显示一次 |

## 2. 第一次登录（只做一次）

1. 在节点上用 SSH 执行（会打印一次性的初始密码，只显示一次，请抄好）：
   ```bash
   sudo -u sws-vault env \
     SWSV_DATA_DIR=/var/lib/sws-vault \
     SWSV_DB_PATH=/var/lib/sws-vault/vault.db \
     SWSV_MASTER_KEY_PATH=/etc/sws-vault/master.key \
     /usr/local/bin/swsvault admin init --generate
   ```
2. 手机打开面板 → 用初始密码登录 → **修改初始密码**（至少 12 位）。
3. **绑定双重验证**：用验证器 App（Google Authenticator、Aegis 等）扫页面上的二维码，输入 6 位码。
4. 重新登录：密码 + 6 位码。之后每次登录都这样。

## 3. 首页

- 顶部一行：密钥数、项目数、最近一次调用时间。
- **新建**：存一个密钥（见第 4 节）。
- **接入项目**：给一个项目生成令牌和配置（见第 5 节）。
- **需要处理 → 未关联密钥**：存了但还没归属任何项目的密钥。它们**任何客户端都调用不了**，点进去把它们接入到项目即可。
- **项目**：每个项目有几个密钥、几个客户端。
- **更多**：所有密钥、审计事件、高级功能。

## 4. 存一个密钥（新建）

1. 首页点 **新建**。
2. 选平台：
   - **Cloudflare**：粘贴 API Token，自动只允许发往 `api.cloudflare.com`。
   - **GitHub**：粘贴 Personal Access Token，自动只允许发往 `api.github.com` / `github.com`。
   - **Gitea**：粘贴 Token，并填你的 Gitea 地址（必须 https）。只会发往这个域名。
   - **通用**：其他服务。需要自己填允许发往的域名，以及注入方式（请求头模板，`{v}` 代表密钥值）。
3. 填一个你自己看得懂的**名称**，比如「博客 Cloudflare DNS」。
4. **关联项目**可以先选「暂不关联」，之后在「接入项目」里再选。
5. 点 **保存**。保存后只显示名称、平台、允许发往的域名，**原值不会再显示**。

## 5. 给项目接入（拿到令牌和配置）

1. 首页点 **接入项目**，填项目名（建议小写英文加横线，比如 `blog-deploy`）。
2. 勾选要给这个项目用的密钥（未关联的和本项目已有的都会列出），点 **生成项目配置**。
3. 结果页给出三段配置，每段右边有 **复制**：
   - **环境变量配置**：`SWSV_URL`、`SWSV_TOKEN`、`SWSV_NS`；
   - **命令调用示例**；
   - **Git 凭据助手配置**。
4. **令牌只显示这一次**。离开页面前复制好，放到目标机器上（见第 6 节）。丢了不能找回：到「高级 → 客户端」停用旧的，再接入一次拿新令牌。

## 6. 在服务器上怎么用

### 6.1 放好配置（推荐）

把「环境变量配置」那三行存成文件，权限必须是 0600：
```bash
install -m 600 /dev/null ~/.config/swsv/blog-deploy.env
# 把三行粘贴进去
```
不要把令牌写在命令行参数里，也不要留在 shell 历史里。

### 6.2 让一个命令用上密钥：`swsvault run`

```bash
swsvault run --env-file ~/.config/swsv/blog-deploy.env \
  --env CF_API_TOKEN=vault:blog-deploy/<密钥ID> -- ./deploy.sh
```
- `--env 变量名=vault:项目/密钥ID`：把密钥放进子进程的这个环境变量（可写多个）；
- `--secret vault:项目/密钥ID`：简写，放进 `SWSV_SECRET`；
- 子进程的输出里如果出现密钥值，会被打码；退出码原样返回。
- 这种方式需要该密钥允许「解析」（resolve），具体在「高级 → 所有密钥 → 使用范围」里设置。

密钥 ID 在「所有密钥」列表里能看到。

### 6.3 git 自动用 GitHub / Gitea 令牌

把结果页的「Git 凭据助手配置」那一行在目标机器上执行一次。之后 `git clone/push` 到对应域名时会自动取令牌；只对绑定了该域名的 GitHub/Gitea 密钥生效。

### 6.4 程序直接调用（API / MCP）

- `POST /v1/fetch`：让保险库**代你发请求**（推荐，项目拿不到明文）。请求体给出 `secret`、`method`、`url`、`headers`，保险库按平台模板注入令牌、只发往允许的域名，返回打码后的响应。
- `POST /v1/resolve`：直接取明文，只在密钥允许 resolve 时可用。
- `/mcp`：给 AI agent 用，提供 `vault_list`、`vault_fetch`、`vault_intent` 三个工具。
- 详细字段见仓库 `docs/api.md`。

## 7. 高级功能（日常用不到）

| 页面 | 用途 |
|---|---|
| 所有密钥 | 列出全部密钥（只有名称、平台、预览、指纹），可按项目、平台筛选；进入单个密钥可改「使用范围」 |
| 项目管理 | 手动创建项目 |
| 客户端 | 查看各项目的客户端令牌（只显示 ID）、**停用**丢失或不用的令牌 |
| 审计事件 | 谁、什么时候、对哪个密钥做了什么，可按项目、操作者、时间筛选 |
| 一次性录入链接 | 生成一个 10 分钟有效、只能用一次的链接，让别人把密钥填进来而不经过聊天 |

## 8. 安全须知

- 现在是明文 HTTP，**只放测试密钥**。
- 客户端令牌只显示一次；泄露了就去「客户端」停用。
- 未关联的密钥谁都调用不了，这是故意的。
- 主密钥在 `/etc/sws-vault/master.key`，数据库备份不包含它，请另外离线保管。

## 9. 常见问题

- **令牌没复制就关了页面？** 停用那个客户端，再接入一次。
- **调用返回「找不到」？** 多半是密钥还没关联到这个项目，或令牌的项目（`SWSV_NS`）写错了。
- **Gitea 用了非 443 端口？** 目前会被拒绝（已知问题，待修）。
- **忘了密码或换了手机验证器？** 在节点上执行 `swsvault admin reset-totp`（需要当前密码）；忘了密码请找 Hark 在节点上处理。
