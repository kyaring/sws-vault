# SWS Vault 使用手册

> 适用版本：dfb77598b566（2026-10-16 部署）。面板地址：`http://192.168.20.132:9531/admin`（仅内网）。
> 当前是**测试部署，走明文 HTTP**：只放测试密钥，正式密钥等 HTTPS 就绪后再录。

## 1. 它是做什么的

SWS Vault 是一个只写不读的密钥保险库。用法分两步：

1. **你**在面板里把密钥（API token 等）存进去，存进去后面板上再也看不到原值；
2. **接入方**（服务器上的脚本、Hub、git 等）拿着自己的**通行证**来调用，保险库只把密钥注入到它被允许发往的地址，接入方本身通常拿不到明文。

记住三个词：

| 词 | 意思 |
|---|---|
| 密钥 | 你存进去的一个值，比如一个 Cloudflare API Token |
| 项目 | 一组密钥的归属，比如 `blog-deploy`。密钥只有关联到某个项目后才能被调用 |
| 通行证 | 发给某个接入方的令牌（`swsv_` 开头），只显示一次 |

## 2. 第一次登录（只做一次）

1. 在节点上用 SSH 执行（会打印一次性的初始密码，只显示一次，请抄好）：
   ```bash
   sudo -u sws-vault env \
     SWSV_DATA_DIR=/var/lib/sws-vault \
     SWSV_DB_PATH=/var/lib/sws-vault/vault.db \
     SWSV_MASTER_KEY_PATH=/etc/sws-vault/master.key \
     /usr/local/bin/swsvault admin init --generate
   ```
2. 手机打开面板 → 用初始密码登录 → **修改初始密码**（至少 12 位）。
3. **绑定双重验证**：用验证器 App（Google Authenticator、Aegis 等）扫页面上的二维码，输入 6 位码。
4. 重新登录：密码 + 6 位码。之后每次登录都这样。

## 3. 三个标签（面板导航）

登录后直接落在 **密钥** 标签。所有已登录页面底部都有三个标签，点一下就能换：

| 标签 | 地址 | 用途 |
|---|---|---|
| 密钥 | `/admin/secrets` | 按项目列出全部密钥；右上角「＋」新建；未归入项目的密钥在最上面 |
| 项目 | `/admin/projects` | 建项目、放密钥、发通行证 |
| 记录 | `/admin/audit` | 谁、什么时候、对哪个密钥做了什么 |

右上角的「设置」里是修改密码、两步验证和退出登录。新建 / 添加 / 编辑类页面不显示标签栏，左上角是「取消」，右下角是主按钮。

## 4. 存一个密钥

1. 「密钥」标签右上角点 **＋**。
2. 选平台：
   - **Cloudflare**：粘贴 API Token，自动只允许发往 `api.cloudflare.com`。
   - **GitHub**：粘贴 Personal Access Token，自动只允许发往 `api.github.com` / `github.com`。
   - **Gitea**：粘贴 Token，并填你的 Gitea 地址（必须 https）。只会发往这个域名。
   - **其他**：其他服务。需要自己填允许发往的域名，以及注入方式（请求头模板，`{v}` 代表密钥值）。
3. 填一个你自己看得懂的**名称**，比如「博客 Cloudflare DNS」。
4. **放进项目（可选）**：不选就先放在「未归入项目」，任何接入方都用不了；也可以从项目详情页的「放入密钥 → 新建密钥」进来，项目会自动选好。
5. 点 **保存**。保存后只显示名称、平台、尾号和所在项目，**原值不会再显示**；接着点「给谁用 →」发一张通行证，或者点「完成」回到这个密钥的详情页。

## 5. 发一张通行证（拿到令牌和配置）

1. 从「给谁用 →」进来：密钥已经在项目里就直接到「添加接入方」；还没归入项目就先选一个项目（或「新建项目」），选完自动跳过去。
2. 填 **名称**（同一个项目里不能重名）和 **备注**（写清楚是谁在用）。
3. 勾选这个使用方 **能用哪些密钥**（**默认一个都不勾**，至少选一个；从「给谁用 →」进来时会预勾那一个密钥）。
4. **权限**两段式选一个，按需决定两件事：
   - **仅代发（推荐，默认）**：新令牌只有「代发」权限（`POST /v1/fetch`），项目拿不到密钥明文。**给 AI 用请选这个。**
   - **可取明文**：只有确实要用 `swsvault run` 或 git 凭据助手时才选。
   - **来源 IP（可选）**：填了以后，只有来自这些地址的调用会被接受。可以写单个 IP 或 CIDR，多个用英文逗号分隔（例如 `10.0.0.0/8, 192.168.1.5`）；单个 IPv4 会自动补成 `/32`，单个 IPv6 补成 `/128`。填错会直接报错，不会创建出半个项目或接入方。
5. 点 **生成通行证**。
6. 结果页按第 4 步的选择给出不同的配置，每段右边有 **复制**：
   - **不勾选取明文（推荐）**：**环境变量配置**、**代发调用示例**（用 `POST /v1/fetch` 让保险库代你发请求；令牌放在环境变量或 `-H @-` 里，不会出现在命令行参数中）、**MCP 配置示例**（`/mcp` 地址加 Bearer 头）。
   - **勾选取明文**：**环境变量配置**、**命令调用示例**（`swsvault run`）、**Git 凭据助手配置**，并额外提醒「此令牌可以取出明文，不要交给 AI」。
   - 如果填了限制来源 IP，结果页会显示生效的 CIDR。
7. **令牌只显示这一次**。离开页面前复制好，放到目标机器上（见第 7 节）。丢了不能找回：到「项目 → 接入方详情」点「重新生成通行证」，旧令牌立刻失效。

> 默认只给代发是故意的：拿到令牌的人可以让保险库替他发请求，但取不到密钥明文。需要明文才选「可取明文」。

## 6. 项目与接入方

「项目」标签里是所有项目，右上角「＋」新建。一个项目 = 一组密钥 + 一批接入方。

1. **建项目**：「项目」标签 → 右上角「＋」。填项目名和一段简介（最多 200 字），说明这个项目里的密钥是干什么的，比如「Cloudflare DNS 令牌，给多个站点复用」。简介以后随时能改，但**密钥值永远看不到**。
2. **放密钥**：项目详情页的「密钥」组最后一行「放入密钥」，里面三个入口——
   - 「新建密钥」：新建表单会预选当前项目（这样建出来的密钥默认不授权给任何接入方）；
   - 「从未归入项目里选」：把还没归入项目的密钥移进来；
   - 「生成录入链接」：10 分钟有效的一次性链接，让对方自己把密钥填进来。
   刚放进来的密钥**不授权给任何接入方**，也不允许取明文，必须在第 3 步勾选才放行。
   已经在项目里的密钥也可以点「项目」行换成别的项目；移出到「未归入项目」要二次确认，并且会同时撤掉所有接入方对它的授权。
3. **添加接入方**：项目详情页底部「添加接入方」。填名称、备注，勾选「能用哪些密钥」（默认不勾，至少一个），选权限（仅代发 / 可取明文），按需填「来源 IP」。详见第 5 节。
4. 提交后给出一次性令牌，并按权限显示对应的配置示例。

**一个密钥多个使用方**：第 3 步在同一个项目里多做几次，每次换一个名称，勾上同一个密钥。每个使用方各拿到一张通行证，可以单独停用——点进「项目 → 接入方详情」，点「停用」只影响那一个，其他使用方照常。

**谁能用哪个密钥**：密钥详情页的「谁在用」和接入方详情页的「能用哪些密钥」写的是同一份数据，两边都能改：勾上就放行、取消就收回。取消最后一个接入方后这个密钥会变成「显式空」——谁都用不了，而不是「项目内所有人都能用」。

**什么时候锁来源 IP**：接入方跑在固定出口 IP 的机器上时（例如某台 CI runner、固定 IP 的服务器），把那个 IP 填进「限制来源 IP」；出口 IP 会变的（家宽、手机热点、Serverless）不要填，否则调用会被 403 拒绝。

## 7. 在服务器上怎么用

### 7.1 放好配置（推荐）

把「环境变量配置」那三行存成文件，权限必须是 0600：
```bash
install -m 600 /dev/null ~/.config/swsv/blog-deploy.env
# 把三行粘贴进去
```
不要把令牌写在命令行参数里，也不要留在 shell 历史里。

### 7.2 让一个命令用上密钥：`swsvault run`

```bash
swsvault run --env-file ~/.config/swsv/blog-deploy.env \
  --env CF_API_TOKEN=vault:blog-deploy/<密钥ID> -- ./deploy.sh
```
- `--env 变量名=vault:项目/密钥ID`：把密钥放进子进程的这个环境变量（可写多个）；
- `--secret vault:项目/密钥ID`：简写，放进 `SWSV_SECRET`；
- 子进程的输出里如果出现密钥值，会被打码；退出码原样返回。
- 这种方式要同时满足两件事：令牌带 `resolve` 权限（在「添加接入方」里选「可取明文」，或在接入方详情页把权限改成可取明文），并且该密钥允许「解析」（resolve，在密钥详情页的「请求限制」里设置）。**默认令牌没有 `resolve`，所以默认用不了 `swsvault run`。**

密钥 ID 在「密钥」标签里点进详情页后，地址栏最后一段就是。

### 7.3 git 自动用 GitHub / Gitea 令牌

把结果页的「Git 凭据助手配置」那一行在目标机器上执行一次。之后 `git clone/push` 到对应域名时会自动取令牌；只对绑定了该域名的 GitHub/Gitea 密钥生效。

只有选了「可取明文」的结果页才有这一段：git 凭据助手同样需要令牌带 `resolve` 权限。

### 7.4 程序直接调用（API / MCP）

- `POST /v1/fetch`：让保险库**代你发请求**（推荐，项目拿不到明文）。请求体给出 `secret`、`method`、`url`、`headers`，保险库按平台模板注入令牌、只发往允许的域名，返回打码后的响应。新令牌默认就有这个权限。
- `POST /v1/resolve`：直接取明文，需要令牌带 `resolve`（在「添加接入方」里选「可取明文」），并且密钥允许 resolve。
- `/mcp`：给 AI agent 用，提供 `vault_list`、`vault_fetch`、`vault_intent` 三个工具。
- 详细字段见仓库 `docs/api.md`。

## 8. 管理（记录与设置）

| 页面 | 用途 |
|---|---|
| 记录（`/admin/audit`） | 谁、什么时候、对哪个密钥做了什么；可按项目、操作者、时间筛选。状态和动作都显示中文 |
| 设置（`/admin/settings`） | 修改密码、两步验证、退出登录 |
| 项目详情 →「编辑」 | 改项目简介（最多 200 字） |
| 密钥详情 | 改「请求限制」（允许的主机、Header 模板、允许解析 / 私网 / HTTP）、轮换、停用 |
| 接入方详情 | 改备注 / 权限 / 来源 IP、改「能用哪些密钥」、重新生成通行证、停用 |
| 生成录入链接 | 10 分钟有效、只能用一次的链接，让别人把密钥填进来而不经过聊天 |

## 9. 安全须知

- 现在是明文 HTTP，**只放测试密钥**。
- 接入方令牌只显示一次；泄露了就点进接入方详情「停用」或「重新生成通行证」。
- 未归入项目的密钥谁都调用不了，这是故意的。
- 主密钥在 `/etc/sws-vault/master.key`，数据库备份不包含它，请另外离线保管。

## 10. 常见问题

- **令牌没复制就关了页面？** 点进接入方详情「重新生成通行证」，旧令牌立刻失效。
- **调用返回「找不到」？** 多半是密钥还没关联到这个项目，或令牌的项目（`SWSV_NS`）写错了。
- **Gitea 用了非默认端口？** 直接填 `https://git.example.com:3000`；使用范围会保留端口（默认端口不写）。
- **忘了密码或换了手机验证器？** 在节点上执行 `swsvault admin reset-totp`（需要当前密码）；忘了密码请找 Hark 在节点上处理。
