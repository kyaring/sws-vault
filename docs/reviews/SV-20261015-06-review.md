### 问题 2 — [建议] 未关联密钥的写路径没有同款守卫

- **证据**：读路径都有 `_unassigned` 守卫（`handlers.go:15` list、`:182` resolve、`fetch.go:27` fetch），但写路径只校验 `q.NS != c.NS`：`create`（`handlers.go:41-65`）与 `rotate`（`:66-90`）没有 `_unassigned` 判断。因此**一个 ns 恰为 `_unassigned` 的 client**（面板客户端表单用 `namePattern`、CLI `client create --ns _unassigned` 都允许创建）可以往未关联区写入/轮换密钥（读取仍被拒）。
- **定性**：**fail-closed 不一致（防御纵深缺口）**。后果：需要运维误配才会出现；一旦出现，该 client 能污染/覆盖未关联密钥（不泄露值，但会造成数据混乱）。触发条件：运维把 client 建在 `_unassigned`；发生概率：低。卡面 A.2 只列举了读路径，故按**建议**处理。
- **建议修法**：`create`/`rotate`/`generate` 加同款 `_unassigned` 守卫（与 resolve 一致的 404），或在建 client 时直接禁止 `_unassigned` 作为 ns。

### 问题 3 — [建议] 「新建」直接关联项目 与「接入项目」的可用范围语义不一致

- **证据**：`admin_quickflow.go:123` 新建时 `Bindings{Hosts: …, AllowResolve: true}`，**不设 `AllowedClients`** → 该项目内**任何**有 `resolve` scope 的 client 都能解析它；而 `admin_quickflow.go:284` 接入项目时 `bd.AllowedClients = []string{clientID}` → **只有本次新建的那个 client** 能用。两条路径在界面上都表现为「关联到项目」，但可用范围不同。
- **定性**：**语义不一致（可能造成意外授权或困惑）**。后果：运维以为「新建并关联项目」= 只给某个客户端用，实际是给该项目所有客户端用；反向地，「接入项目」的密钥在后续新增客户端时不可用（需手工改使用范围）。触发条件：项目内有多个 client；发生概率：中。
- **建议修法**：统一语义并在结果页写明（例如「该项目内所有客户端均可使用」或「仅本次生成的客户端可用」），或给「新建」也提供「仅限某个客户端」的选项。

### 问题 4 — [建议] QR 生成失败时没有备用路径

- **证据**：`admin_enroll.go:148-152` `qr, e := qrSVG(uri); if e != nil { errOut(w, 500, "QR generation failed"); return }` —— 一旦 QR 生成失败（`qr.go:12` 的 106 字节上限），页面直接 500，**卡面 F.2 要求的「可复制的密钥文本作为备用」也不会出现**。当前 URI 长度固定为 76 字节（`otpauth://totp/admin?secret=` 28 + 32 + `&issuer=SWSVault` 16），距上限有 30 字节余量，所以现实不可达。
- **定性**：**可用性（潜在单点失败）**。后果：若将来改动 label/issuer 或换更长的秘钥编码，管理员会看到 500 而没有任何绑定手段。触发条件：修改 URI 组成；发生概率：低。
- **建议修法**：QR 失败时仍渲染页面并只显示手动密钥（提示「请手动输入」），或改用能容纳更长 payload 的 QR 版本。
