## 背景
OPC 10-16 07:1x 反馈：入口重复、到处套娃、概念不清——首页「新建」「接入项目」和下面的「高级 / 所有密钥 / 审计」重复；「未关联」点进去又是一个「所有密钥」；高级里的「客户端」和项目里的「接入方」是同一个东西。本卡把面板收拢成**三个标签、每个功能只有一个入口、每个对象只有一个详情页**。后端权限语义（SV-04/05/06）一律不改，只重排页面并补一个编辑接口。

## 术语（面板上只许用这三个词）
- **密钥**：存进来的 token / key，值永不显示。
- **项目**：一组密钥的用途归类。没有项目的密钥叫「未归入项目」（原「未关联」）。
- **接入方**：谁来调用，一个接入方一张通行证。
全站管理页不得出现：命名空间、客户端、client（显示文字）、高级、意图、intent、接入项目、未关联、绑定。测试用固定字符串断言（只查用户可见文本，不查 URL 和 name 属性）。

## 要做

### A. 导航骨架
1. 所有已登录管理页底部固定标签栏：「密钥」`/admin/secrets`、「项目」`/admin/projects`、「记录」`/admin/audit`，当前页高亮（`aria-current="page"`），每项触控区 ≥44px，iOS 安全区用 `env(safe-area-inset-bottom)`。表单类页面（新建 / 添加 / 编辑）不显示标签栏，顶部改为「取消」+ 标题。
2. 右上角「设置」→ `/admin/settings`：修改密码、两步验证、退出登录三行；原 `/admin/password`、`/admin/totp/enroll` 地址不变，只是从这里进入。
3. 登录后、`/admin/` 都 303 到 `/admin/secrets`。原首页的磁贴和分组入口全部删除。
4. 旧地址一律 303：`/admin/advanced`、`/admin/advanced/secrets`（保留 query 里的筛选参数也无妨，但页面就是新的密钥标签）→ `/admin/secrets`；`/admin/clients` → `/admin/projects`；`/admin/namespaces` 继续 → `/admin/projects`；`GET /admin/quick/project` → `/admin/secrets/new`。POST 到旧地址的行为：`/admin/quick/project` 的 POST 保留原处理（SV-04 测试不得改断言），其余旧 POST 地址保持原处理不变。
5. 返回逻辑：详情页左上角「‹ 上级」固定指向上级页面（密钥详情→密钥，项目详情→项目，接入方详情→所属项目），不依赖浏览器历史。

### B. 密钥标签 `/admin/secrets`（设计稿 ①）
- 按项目分组列出全部密钥；「未归入项目 · N」组置顶（N=0 时不显示该组）；项目组按名称排序。
- 每行：图标、名称、副标题「平台 · 尾号 xxxx · 接入方数 / 已停用 / 还没人能用」，整行可点进密钥详情。尾号沿用现有的预览逻辑，**不得新增任何能还原值的显示**。
- 右上角「＋」→ `/admin/secrets/new`。
- 原「所有密钥」的筛选：密钥数 >20 时在顶部显示一个搜索框（按名称 / 平台过滤，GET 参数），否则不显示。原 JSON 输出和横向溢出的表格删除。

### C. 新建密钥 `/admin/secrets/new`（设计稿 ②③）
- 字段：平台（Cloudflare / GitHub / Gitea / 其他，单选胶囊）、名称、密钥值（password 输入，autocomplete=off）、放进项目（可选，下拉；支持 `?project=` 预选）。提示文案「不选就先放在『未归入项目』，任何接入方都用不了。」
- 使用范围（原 bindings）由平台模板自动生成，表单上不出现；Gitea 自建地址等模板参数照旧放在选「Gitea / 其他」后才出现的字段里。
- 成功页（③）：显示名称 · 平台 · 尾号、所在项目；两个按钮「给谁用 →」「完成」。
  - 「给谁用 →」：已在项目里 → `/admin/projects/{name}/clients/new?secret={id}`（预勾该密钥）；未归入项目 → 先到「放进哪个项目」选择页（列出现有项目 + 「新建项目」），选完把密钥移入后再跳到添加接入方。
  - 「完成」→ 密钥详情。
- 原「接入项目」一步式流程不再有任何入口（POST 处理保留，见 A4）。

### D. 密钥详情 `/admin/secrets/{id}`（设计稿 ⑦，新增路由）
- 头部：名称、平台 · 尾号 · 指纹前 8 位。
- 「项目」行：显示所属项目，点进可「移到项目…」（选择页同 C；移出到「未归入项目」时要二次确认，并同时从所有接入方的授权里移除该密钥）。
- 「最近使用」：时间 + 接入方名。
- 「谁在用」：列出**所属项目内**的全部接入方，每行一个开关（开=该接入方在此密钥的 AllowedClients 中）。开关是一个 form + checkbox + 「保存」按钮也可以，不强制 JS；若用 JS 自动提交，必须有无 JS 的回退。
- 「请求限制」：折叠行，展开即原 `/admin/secrets/{id}/bindings` 的使用范围编辑（原地址保留，作为这一折叠区的提交地址或 303 到详情页均可），摘要显示第一个 host。
- 按钮：轮换、停用（复用现有 rotate / disable 处理，结果回到详情页）。

### E. 项目标签 `/admin/projects` 与项目详情（设计稿 ④）
- 列表不变（名称、简介、密钥数、接入方数），右上角「＋」新建项目。
- 详情页：「密钥」组每行进密钥详情；末行「放入密钥」→ 小页面三项：「新建密钥」（`/admin/secrets/new?project=`）、「从未归入项目里选」（沿用现有移入逻辑）、「生成一次性录入链接」（即原 `/admin/intents/new`，项目字段固定为本项目，结果页展示 10 分钟有效链接，文案叫「录入链接」）。
- 「接入方」组每行进接入方详情（不再在列表行上放「停用」按钮）。底部「添加接入方」主按钮。

### F. 添加接入方 `/admin/projects/{name}/clients/new`（设计稿 ⑤）
- 「高级」折叠区取消：权限做成两段式选择「仅代发（推荐）/ 可取明文」，下方一句说明；来源 IP 直接作为可选字段显示。
- 支持 `?secret={id}` 预勾；没有该参数时**默认不勾任何密钥**（与 SV-06「从项目新建的密钥默认未授权」方向一致；至少选一个的校验保留）。
- 语义、事务、`authorizeProjectSecrets` 的空授权显式化逻辑完全不变；结果页（一次性通行证）不变。

### G. 接入方详情 `/admin/projects/{name}/clients/{id}`（设计稿 ⑥，新增）
- 显示名称、备注、创建时间、权限（仅代发 / 可取明文；scopes 不是这两种之一的旧接入方显示「自定义」并只读列出 scopes）、来源 IP（空=不限）、状态 + 最近使用。
- 「能用哪些密钥」：本项目全部密钥，每行一个开关，与 D 的「谁在用」写的是同一份 AllowedClients 数据。
- 可编辑：备注、权限、来源 IP（复用 SV-04 的 CIDR 规范化与 400 校验）。权限从「可取明文」改回「仅代发」时去掉 resolve scope；改成「可取明文」时按 SV-04 规则对其已授权密钥设 AllowResolve=true，且不得把未授权给它的密钥改成 true。
- 按钮：「重新生成通行证」（旧令牌立即失效，新令牌只显示一次，复用 SV-04 结果页渲染）、「停用」（复用现有 disable）。
- 跨项目访问（URL 里的项目与接入方所属不符）一律 404。

### H. 授权开关接口（D、G 共用，新增）
- `POST /admin/secrets/{id}/clients`（表单：接入方 id 列表）与 `POST /admin/projects/{name}/clients/{id}/secrets`（表单：密钥 id 列表），各自整体覆盖该维度的授权，单事务。
- 规则：只能授权**同一项目**内的密钥与接入方，跨项目的 id 一律 400 且库不变；未归入项目的密钥不可授权给任何人；关掉最后一个授权后，该密钥的 AllowedClients 变为「显式空」而不是「空=全部」（复用 SV-06 的 no_client_access 语义，绝不能退回「空列表=所有人可用」）；需要 CSRF；审计记一条 `admin.grant.update`（只记 id，不记值）。
