## 背景（OPC 10-16 03:24 决定）
这个项目的初衷是不让 AI 拿到密钥明文。现在「接入项目」快速流程（internal/api/admin_quickflow.go）有两个问题：
- 创建客户端时 scopes 写死为 `secrets:list,resolve,fetch`，cidrs 为空（约第 325 行）；
- 被接入的密钥会被强制设置 `bd.AllowResolve = true`（约第 371 行）。
结果就是：任何拿到客户端令牌的人都能通过 `/v1/resolve` 取到明文，而且可以从任意 IP 调用。

## 要做
A. **默认只给代发**：快速流程新建的客户端 scopes 默认是 `secrets:list,fetch`，不再包含 resolve。
B. **取明文改为可选**：「接入项目」表单增加一个复选框，文案「允许取出明文（命令注入 / git 需要）」，默认不勾选，放在可折叠的「高级」区域（details），并附一句说明：「给 AI 用请不要勾选」。
   - 勾选：scopes 加上 resolve，被选中的密钥设置 `AllowResolve = true`（即当前行为）。
   - 不勾选：从「未关联」移过来的密钥 `AllowResolve = false`；已经属于本项目的密钥，保留其原有的 AllowResolve 不变（不得因为这次没勾选就把它改成 true）。
C. **锁定来源 IP**：表单增加一个可选输入框「限制来源 IP」，接受逗号分隔的 IP 或 CIDR。单个 IPv4 转成 /32，单个 IPv6 转成 /128；非法值返回 400，错误页显示中文提示，且不能创建出半成品的项目或客户端（整体放在一个事务里）。写入 clients.cidrs。复用现有的 `ipAllowed`、`sourceIP` 逻辑，不得修改它们的语义。
D. **结果页按权限显示**：
   - 未勾选 resolve：不显示 `swsvault run` 和 Git 凭据助手两段，改为显示「代发调用示例」（用环境变量调 `POST /v1/fetch` 的 curl 示例，令牌放在 `-H @-` 或环境变量里，不出现在 argv 中），以及「MCP 配置示例」（`/mcp` 地址加 Bearer 头的占位写法）；同时用一句话说明：此令牌只能代发请求，不能取出明文。
   - 勾选 resolve：维持现在的三段，另加一句提醒：此令牌可以取出明文，不要交给 AI。
   - 如填了限制来源 IP，结果页要显示生效的 CIDR。
E. **文档**：更新 docs/USER-GUIDE.md 第 5、6 节，写明默认只能代发、什么时候才需要勾选取明文、如何锁定 IP；docs/api.md 补充快速流程的默认 scopes。

## 测试（全部在 internal/api 的 _test.go 中）
1. 默认接入：新客户端的 scopes 不含 resolve；用它调 `/v1/resolve` 返回 403；调 `/v1/fetch`（指向测试后端、已绑定的主机）成功。
2. 勾选取明文：scopes 包含 resolve，调 `/v1/resolve` 成功。
3. 不勾选时，已属于本项目且原本 `AllowResolve=true` 的密钥保持 true；从未关联移入的密钥为 false。
4. 限制来源 IP：填 `10.9.9.9`，存储为 `10.9.9.9/32`；从不在范围内的来源 IP 调用返回 403，在范围内的调用成功（用 httptest 设置 RemoteAddr）。
5. 非法 CIDR 返回 400，且数据库中没有新增项目或客户端。
6. 结果页：默认模式的 HTML 不含 `swsvault run` 和 `git-credential`，包含 `/v1/fetch`；勾选模式与之相反。任何模式下页面和日志都不得包含密钥明文。
