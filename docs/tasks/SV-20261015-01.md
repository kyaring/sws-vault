## 四、里程碑与要求

### M1 骨架与配置
- 目录结构：`cmd/swsvault/`（单一入口，带子命令）；`internal/{config,crypto,store,api,auth,provider,fetch,mcp,panel,audit,cli}`；面板模板和静态文件放 `web/`，用 embed 打包。
- 子命令：`serve`、`keygen`、`admin init`、`admin reset-totp`、`client create`、`run`、`capture`、`git-credential`、`version`。
- 配置：用 `--config` 指定文件（KEY=VALUE 格式），也可以用环境变量 `SWSV_*` 覆盖。默认值：监听 127.0.0.1:9531；数据库 /var/lib/sws-vault/vault.db；主密钥 /etc/sws-vault/master.key；`public_base_url` 留空。测试一律用临时目录。

### M2 存储与信封加密
- 表：`namespaces`、`clients`、`secrets`、`intents`、`audit`、`admins`、`sessions`，带 schema_version 迁移。
- 每条 secret 生成一把随机 32 字节的 DEK，用 AES-256-GCM 加密值，AAD 为 `ns|id|type|key_version`。DEK 由 KEK（主密钥经 HKDF 派生）用 AES-GCM 包裹。
- `keygen`：只在文件不存在时生成 32 字节随机主密钥，写入后权限为 0600，**绝不输出到 stdout 或日志**；文件已存在就拒绝覆盖。
- `serve` 启动时，主密钥文件权限宽于 0600 就拒绝启动。
- 支持多版本 KEK：`master.key` 可以带 `.v2` 等新版本；提供 `rotate-kek` 内部函数并写测试，用来重新包裹全部 DEK（本期不做 UI）。
- 每条 secret 都存 preview（login 显示打码的用户名，其余显示末 4 位；webhook 只显示主机名）和 fingerprint（HMAC-SHA256(KEK 派生子钥, 值) 的前 12 位十六进制）。不存明文的哈希。

### M3 鉴权、namespace、client、审计
- client 令牌格式为 `swsv_` 加 43 位 base64url 随机串，只存 SHA-256 哈希；令牌只在创建时显示一次（CLI 或面板）。
- client 字段：ns、名称、scopes（`secrets:list`、`secrets:write`、`fetch`、`resolve`、`intents:create`）、来源 IP 的 CIDR 白名单（可以为空）、过期时间、停用标记。
- 每个 client 单独限流（令牌桶，默认每分钟 60 次，可配置）；超限返回 429。
- 审计：每次 list、write、fetch、resolve、intent、登录、管理操作都记一行，包括时间、client 或 admin、ns、secret id、动作、目标主机、结果、来源 IP。**审计里绝不记值、请求头或响应体。**

### M4 REST `/v1`（对外）
- `GET /v1/secrets?ns=`：只返回元数据（id、label、provider、type、preview、fingerprint、bindings、created_at、rotated_at、last_used_at、status）。
- `POST /v1/secrets`：录入，值在 JSON 的 `value` 字段，只能写入；`PUT /v1/secrets/{id}/value`：轮换。两者都需要 `secrets:write`，并且只返回元数据。
- `POST /v1/generate`：保险库自己生成随机值（参数为长度和字符集），只返回元数据。
- `POST /v1/intents`：生成一次性录入链接，10 分钟有效，只能用一次，返回 `{public_base_url}/i/<token>`；intent 令牌只存哈希。
- `POST /v1/fetch`：出站注入，详见 M6。
- `POST /v1/resolve`：仅供 CLI 的 run 和 git-credential 使用；需要 `resolve` scope，并且 secret 的 bindings 里开启了 `allow_resolve`。返回值时响应头带 `Cache-Control: no-store`。这是全系统**唯一**返回明文的出口，只给已登记的节点 client 用，每次都审计。
- 管理类接口（建 ns、建 client、停用、改绑定）只在 `/admin/*` 下，靠面板会话加 CSRF 鉴权，不对 client 令牌开放。
- 写 docs/api.md。

### M5 管理面板（OPC 亲自录入）
- `admin init` 在终端交互：密码从 stdin 读两次（不回显），生成 TOTP 密钥，在终端输出一次 otpauth URI（**不写日志**）。`admin reset-totp` 同理。
- 登录：密码（argon2id）加 TOTP（允许前后各 1 个时间窗，同一个码不能用两次）。会话 cookie 设 HttpOnly、Secure（public_base_url 是 https 时）、SameSite=Strict，空闲 15 分钟、最长 8 小时过期。登录失败做退避，连续 5 次失败锁定 15 分钟。
- 页面：
  - 列表：可按 ns、平台筛选，显示 preview、fingerprint、绑定、最近使用时间和状态。
  - 新建：选平台模板，填标签、值（password 输入框，autocomplete=off）和 base_url，勾选「保存前验证」。
  - 轮换：覆盖写。
  - 停用。
  - 改绑定：主机白名单、header 模板、allowed_clients、allow_resolve、allow_private。
  - namespace 管理；client 管理（创建后只显示一次令牌）。
  - 审计查询：分页，可按时间、ns、client 筛选。
  - 一次性录入链接：可以在面板里发起；`/i/<token>` 页面不用登录，只能提交一次。
- 每个表单都带 CSRF 令牌；所有响应带 CSP `default-src 'self'`、X-Frame-Options DENY 和 Referrer-Policy no-referrer。面板**任何页面都不出现明文值**，回显时密码框保持为空。
- 界面用中文，只用 html/template 和少量原生 CSS，不用前端框架、不用 JS 构建。

### M6 平台模板与出站注入
- 平台模板放在 `internal/provider/`，用数据表驱动，新增平台只加条目：

| provider | 注入 | 默认主机 | 验证 |
|---|---|---|---|
| cloudflare-token | `Authorization: Bearer {v}` | api.cloudflare.com | GET /client/v4/user/tokens/verify，success 为 true |
| cloudflare-global-key | `X-Auth-Email: {username}` 和 `X-Auth-Key: {v}`（login 类型） | api.cloudflare.com | GET /client/v4/user |
| github-pat | `Authorization: Bearer {v}` | api.github.com | GET /user 返回 200 |
| gitea-token | `Authorization: token {v}` | base_url 的主机（必填） | GET {base_url}/api/v1/user 返回 200 |
| generic | 自定义 header 模板（只能用 `{v}` 和 `{username}`） | 手填 | 可选手填一个 URL，返回 2xx 即通过 |

- 验证请求同样走 fetch 引擎，同样受白名单约束。验证失败不入库，并返回平台给的错误码，不带响应体原文。
- `POST /v1/fetch` 的参数：`{secret: "vault:<ns>/<id>", method, url, headers, body}`。
  - 只允许 https；只有 bindings 里显式写了 `allow_http` 才放行 http（Gitea 内网用）。
  - URL 的主机必须**精确匹配**白名单，不支持通配；端口要么在白名单里写明，要么是默认端口。
  - 防 SSRF：先解析 DNS，拒绝 loopback、link-local、私网、metadata 地址，除非 bindings 有 `allow_private`；拨号时**固定使用已校验的 IP**，防 DNS rebinding。
  - 不自动跟随重定向，3xx 原样返回，Location 头脱敏。
  - 调用方传来的 Authorization、X-Auth-*、Cookie 一律丢弃，以注入的为准。
  - 超时 15 秒；响应体上限 1 MB，超出截断并标记。
  - 响应头和响应体里出现注入值的（原文、base64、URL 编码三种形式），一律替换为 `[REDACTED]`。
- 写 docs/providers.md。

### M7 MCP 与 CLI
- MCP 端点 `/mcp`：streamable HTTP，鉴权用 Bearer client 令牌。实现 initialize、tools/list、tools/call，提供三个工具：`vault_list`、`vault_fetch`、`vault_intent`。行为和权限与 REST 完全一致，复用同一套 service 层。
- CLI（读取 `SWSV_URL`、`SWSV_TOKEN`，或用 `--env-file` 指定文件，文件权限必须 0600）：
  - `swsvault run --env NAME=vault:ns/id [...] -- cmd args`：调 resolve 取值，只注入子进程的环境变量，不写盘；子进程的 stdout 和 stderr 实时脱敏后再转发；退出码透传。
  - `swsvault capture --ns X --label Y --provider P [--username U]`：值只从 stdin 读，调用 `POST /v1/secrets`，只输出 id 和 preview。
  - `swsvault git-credential get|store|erase`：实现 git credential helper 协议，get 时按 host 匹配到 bindings 里开启了 allow_resolve 的 github-pat 或 gitea-token，返回 `username=x-access-token` 和 password；store 和 erase 不做任何事。
  - `swsvault client create --ns X --name Y --scopes ...`：本机管理命令，直接操作数据库，只有 root 能用；令牌只输出一次。
- README 写清楚三种调用方式的示例，示例里只用假值。

## 五、测试（必须有，否则不予审核）
1. 加密：往返解密；AAD 错位时解密必须失败；KEK 轮换后能读旧值；篡改密文必须失败。
2. **哨兵测试**（tests 放在 `internal/...`）：录入值 `SENTINEL-VALUE-7f3a9c`，之后断言以下地方都**不出现**这个值（包括原文、base64、URL 编码三种形式）：
   - 数据库文件的原始字节；
   - 审计表；
   - 所有 `/v1`、`/admin`、`/mcp` 接口的响应（除 resolve 以外）；
   - 面板各页面的 HTML；
   - 服务日志的输出；
   - fetch 的响应（用本地 httptest 服务把收到的请求头回显回来，以此验证 fetch 会脱敏）。
3. fetch 安全：拒绝不在白名单的主机；拒绝私网和 metadata 地址；不跟随重定向；丢弃调用方的 Authorization；DNS rebinding 测试要证明拨号用的是固定 IP；校验响应体上限。测试中可以通过注入 resolver、dialer 让 httptest 服务被视为放行。
4. 鉴权：scope 不足返回 403；跨 ns 访问返回 404；停用或过期的 client 返回 401；限流返回 429；CIDR 不符返回 403。
5. 面板：CSRF 缺失时拒绝；TOTP 同一个码重放时拒绝；连续 5 次失败后锁定；会话超时；所有页面都带安全响应头。
6. intent：只能用一次；过期后失效；令牌只存哈希。
7. 平台模板：四个平台的注入头格式和验证 URL 都正确（用 httptest 模拟平台返回）。
8. CLI：run 的退出码透传，输出脱敏；git-credential 的协议输入输出；env-file 权限宽于 0600 时拒绝。
9. MCP：tools/list 返回三个工具；tools/call 的权限与 REST 一致。
10. 反向验证（在交付报告里写明怎么做的、结果如何）：临时把 fetch 的脱敏关掉，哨兵测试必须失败；临时让 list 返回明文，哨兵测试必须失败。做完要恢复，不能提交。
