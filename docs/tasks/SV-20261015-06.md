## 背景

- 面板上不能出现「命名空间」「namespace」「NS」。统一叫「项目」，存密钥时的选项叫「关联项目」。代码、API、数据库里的 namespace 名字保持不变，只改界面文案。
- 不设默认分类。存密钥时如果没选关联项目，该密钥就是「未关联」，任何 client 都调用不了。
- 首页给两个快捷入口，把其他功能收进「高级」。

## A. 未关联状态（后端）
1. 允许创建不属于任何项目的密钥（数据模型自定，例如保留 ns 名 `_unassigned`，或 ns 允许为空，二选一并写进 security.md）。
2. 未关联的密钥：resolve、run、git-credential、出站注入全部拒绝，按「不存在」返回同样的错误，不泄露该密钥存在；`/v1` 的 list 也不返回。
3. 面板上的「关联项目」操作：把一个未关联密钥移入某个项目，并可选同时创建使用绑定；移入后不可再改回未关联（如要停用，用现有的 disable）。整个过程写审计（actor=admin，不含值）。
4. 迁移：现有数据不受影响，schema_version 递增，迁移可重复执行。

## B. 快捷入口一：「存一个密钥」（首页大按钮）
- 一页完成：选平台（Cloudflare、GitHub、Gitea、通用，复用 S-4b 模板）→ 填名称 → 粘贴值（password 输入框）→ 关联项目下拉（第一项为「暂不关联」，下面列出已有项目）→ 保存。
- 平台模板自动带出用途和默认绑定（例如 GitHub 绑 github.com），用户不用懂绑定。
- 保存后的结果页只显示名称、平台、关联状态，绝不回显值。
- 仍走 CSRF、会话校验和 TOTP 会话。

## C. 快捷入口二：「给项目接入」（首页大按钮）
- 输入项目名（小写字母、数字、连字符）→ 勾选要关联给这个项目的密钥（列出未关联的和已在该项目里的，可不勾）→ 生成。
- 后台一次完成：创建项目（ns），把勾选的密钥移入并建好绑定，创建 client 令牌。
- 结果页只显示一次令牌，并给出三段可复制的示例：环境变量配置、`swsvault run --secret <名> -- <命令>`、git-credential 配置。示例里的令牌用实值，提示「只显示这一次」。
- 项目已存在时提示「追加接入」，不报错；令牌每次新建一个，旧令牌不动。

## D. 首页与文案
- 首页：两个大按钮，下面是项目列表（项目名、密钥数、客户端数），以及未关联密钥的数量和入口。
- 现有页面（密钥、客户端、审计、轮换、一次性录入链接等）收进「高级」，功能保留。
- 界面上所有「命名空间」「namespace」「NS」改为「项目」；全仓搜索 web 和模板输出，做到零残留（审计页的筛选也改）。
- 不做视觉美化，但要有最基本的可读排版（admin.css 可写几十行，不引外部资源，CSP 不放宽）。

## E. 文档
- ops.md 补一节「快速上手」，五步以内：初始化管理员 → 登录 → 存一个密钥 → 给项目接入 → 在项目里调用。
- security.md 写明未关联状态的拒绝语义，以及 C 节里令牌只显示一次。
