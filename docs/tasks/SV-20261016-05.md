## 背景（OPC 10-16 04:49 提出，04:52 定由 RikkaHub-1 开发）
现在「接入项目」一步把「建项目、放密钥、发通行证」做完，OPC 认为应拆开：
1. 先建项目，写一段简介说明这个项目里的密钥是干什么的（以后看不到密钥值，但能看到简介）；
2. 再单独「添加接入方」：谁要用这个项目里的东西，就给谁发一张通行证。
典型场景：一个只有 DNS 权限的 Cloudflare Token 放在项目 cf-dns，被多个项目复用，每个使用方各一张通行证，可单独停用。
现有一步式「接入项目」保留，作为快捷方式，行为不变（SV-04 的默认值必须保持）。

## 要做
A. **数据（internal/store/）**：幂等的增量迁移，参照 store.go 里 admins 的 PRAGMA table_info 写法：
   - namespaces 加 `description TEXT NOT NULL DEFAULT ''`；
   - clients 加 `note TEXT NOT NULL DEFAULT ''`。
   旧库升级后原有数据不变；迁移跑两次不报错。简介 ≤200 字、备注 ≤100 字（按 rune 计），超长返回 400。两者都只是说明文字，不得写入任何密钥值。
B. **项目列表 `/admin/projects`**：每行显示项目名、简介（截断）、密钥数、接入方数，点进详情。系统保留的「未关联」不出现在列表里。首页增加「项目」入口；旧的 `/admin/namespaces` 改为 303 跳转到 `/admin/projects`。
C. **新建项目 `/admin/projects/new`**：表单只有「项目名」「简介」。名称校验、保留名拒绝沿用现有逻辑（admin_extra.go 里的「这是系统保留名称」），重名返回 400。成功后跳到项目详情页。需要 CSRF，与现有表单一致。
D. **项目详情 `/admin/projects/{name}`**：
   - 顶部：项目名 + 简介，简介可编辑（POST，CSRF）。
   - 「密钥」组：每行名称、平台、状态、最近使用，绝不显示值或可还原值的内容；入口「新建密钥」（新建表单预选本项目）和「从未关联移入」（只列出「未关联」的密钥；移入后 AllowResolve=false、不授权给任何接入方，需在添加接入方时勾选）。
   - 「接入方」组：每行名称、备注、权限（显示为「仅代发」或「可取明文」）、来源 IP（空则显示「不限」）、状态、创建时间；每行「停用」按钮复用现有 `/admin/clients/{id}/disable`。
E. **添加接入方 `/admin/projects/{name}/clients/new`**：
   - 字段：名称（同项目内不得重名，重名 400）、备注（可选）、可使用的密钥（本项目密钥的复选列表，默认全选，至少选一个）、高级（折叠 details）里放「允许取出明文」复选框（默认不勾，附「给 AI 用请不要勾选」）和「限制来源 IP（可选，留空不限）」。
   - 语义与 SV-04 完全一致：默认 scopes `secrets:list,fetch`；勾选才加 resolve 并对所选密钥设 AllowResolve=true；不勾选不得把已有密钥的 AllowResolve 改成 true；CIDR 规范化与非法值 400 复用 SV-04 的函数；所选密钥把新 client id 追加到 AllowedClients；整体一个事务，失败不留半成品。
   - 结果页：通行证只显示一次，示例按权限显示（同 SV-04），并吸收下面 G 的两条修正。建议把 SV-04 结果页的渲染抽成共用函数，两处共用。
F. **「所有密钥」页 `/admin/advanced/secrets`（admin.go 约 230 行的旧模板）**：去掉顶部那排下划线链接，改成与首页一致的分组行式入口（返回首页、新建、项目、审计等）；筛选区默认收进折叠的 details。列表内容与现有接口不变。
G. **SV-04 遗留三条 Low**：
   1. 代发示例不得出现 `export SWSV_TOKEN=<令牌>` 这种会进 shell 历史的写法，改为 `read -rs SWSV_TOKEN` 交互读入，或写入 0600 的 env 文件后 `set -a; . 文件; set +a`；页面上的令牌本体只出现在那一个「复制」框里。
   2. MCP 示例旁加一句：`${SWSV_TOKEN}` 是否展开取决于客户端；不展开的客户端要把令牌直接填进它自己的密钥配置，不要写进会提交到仓库的文件。
   3. 即 F。
H. **文档**：USER-GUIDE.md 增加「项目与接入方」一节（建项目 → 放密钥 → 添加接入方，一个密钥多个使用方的做法，什么时候锁 IP）；api.md 补充新增的管理路由。

## 测试（全部在 internal/api 或 internal/store 的 _test.go 中）
1. 迁移：旧结构的库升级后有两个新列、原数据不变；连续迁移两次不报错。
2. 新建项目：成功后列表和详情都能看到简介；保留名、重名、简介超长分别返回 400，且库中无新增。
3. 添加接入方（默认）：scopes 不含 resolve；用它调 `/v1/resolve` 返回 403；调 `/v1/fetch` 到已绑定的测试后端成功；未勾选的密钥不在其 AllowedClients 中，调用该密钥被拒。
4. 添加接入方（勾选取明文）：scopes 含 resolve，`/v1/resolve` 成功；不勾选时已有 AllowResolve=true 的密钥保持 true，移入的密钥为 false。
5. 同一项目两个接入方共用一个密钥：都能代发；停用其中一个后它被拒、另一个仍可用。
6. 来源 IP：填单个 IP 存为 /32；范围外 403、范围内成功；非法值 400 且无半成品。
7. 页面：详情页、列表页、结果页、所有密钥页的 HTML 不含任何密钥明文；结果页不含 `export SWSV_TOKEN=`；所有密钥页不再含旧的下划线链接条（按旧模板里的一个固定片段断言），筛选区在 details 内；全站管理页不含「命名空间」。
8. CSRF：新建项目、编辑简介、添加接入方、移入密钥缺 CSRF 时都返回 403。
9. 快捷「接入项目」回归：SV-04 已有测试原样通过，不得修改它们的断言。
